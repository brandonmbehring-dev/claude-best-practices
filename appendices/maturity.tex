\chapter{The Claude Maturity Model}
\label{app:maturity}

This model provides concrete milestones for Claude Code adoption.
Use it to assess where you are and what to invest in next.
Each Part introduction in this handbook references the levels below.

\section{Five Levels of Claude Adoption}
\label{sec:maturity-levels}

\begin{fullwidth}
\begin{tabular}{@{}clp{4cm}p{5cm}@{}}
\toprule
\textbf{Level} & \textbf{Name} & \textbf{Key Capabilities} & \textbf{Milestone} \\
\midrule

\maturitylevel{2} & Configured & CLAUDE.md, custom commands, permissions, basic hooks &
  5+ commands in a workflow chain \\[6pt]

\section{Upgrade Checklists}

\subsection{L1 $\rightarrow$ L2: From Conversational to Configured}

\begin{itemize}
  \item[$\square$] Create CLAUDE.md with build commands and code conventions
  \item[$\square$] Add \code{.claude/settings.json} with deny rules for secrets
  \item[$\square$] Create 3+ custom commands for common workflows
  \item[$\square$] Add PostFileWrite hook for auto-formatting
  \item[$\square$] Add PreCommit hook for test suite
\end{itemize}

Reference: \cref{ch:first-claude-md}, \cref{ch:first-session}

\subsection{L2 $\rightarrow$ L3: From Configured to Systematic}

\begin{itemize}
  \item[$\square$] Create hub directory for shared patterns
  \item[$\square$] Convert 3+ projects to hub-and-spoke imports
  \item[$\square$] Add conditional rules (\code{paths:} frontmatter) for distinct modules
  \item[$\square$] Use sessions with named checkpoints (\code{/rename})
  \item[$\square$] Maintain CURRENT\_WORK.md for cross-session context
  \item[$\square$] Create first plan document for a large task
  \item[$\square$] Use thinking-partner techniques (hypothesis debugging, assumption surfacing)
\end{itemize}

Reference: \cref{ch:architecture}, \cref{ch:context}, \cref{ch:thinking-partner}

\subsection{L3 $\rightarrow$ L4: From Systematic to Autonomous}

\begin{itemize}
  \item[$\square$] Create skills for repeated multi-step workflows
  \item[$\square$] Add MCP server for external tool access
  \item[$\square$] Define custom subagents for specialized tasks
  \item[$\square$] Implement writer/reviewer pattern for code review
  \item[$\square$] Build traffic-light quality dashboard
  \item[$\square$] Run parallel workflows with git worktrees
\end{itemize}

Reference: \cref{ch:extending}, \cref{ch:agents}

\subsection{L4 $\rightarrow$ L5: From Autonomous to Enterprise}

\begin{itemize}
  \item[$\square$] Deploy managed-settings.json for organization-wide policy
  \item[$\square$] Implement headless mode in CI/CD pipeline
  \item[$\square$] Establish team CLAUDE.md standards committed to VCS
  \item[$\square$] Set up SSO and audit logging
  \item[$\square$] Build fan-out automation for bulk operations
  \item[$\square$] Track usage metrics and cost optimization
\end{itemize}

Reference: \cref{ch:automation}, \cref{ch:team}, \cref{ch:enterprise}

\section{Progression Strategy}

\practitioner{Promote when friction justifies it, not on a schedule.}

\begin{enumerate}
  \item \textbf{Stay at L1} until you find yourself repeating the same
    context to Claude across sessions.
  \item \textbf{Move to L2} when CLAUDE.md and 3--5 commands would
    eliminate daily repetition.
  \item \textbf{Move to L3} when 3+ projects share patterns
    or when plans would prevent wasted effort on large tasks.
  \item \textbf{Move to L4} when multi-step workflows consume
    significant time or external tools would unlock new capabilities.
  \item \textbf{Move to L5} when team adoption, compliance, or production
    automation requires enterprise infrastructure.
\end{enumerate}

\begin{warnbox}[Premature Promotion]
Jumping from L1 to L4 is a common mistake.
Each level builds on the habits and infrastructure of the previous one.
Skills without CLAUDE.md produce inconsistent results;
MCP servers without permissions create security risks;
agent teams without plan documents produce uncoordinated work.
\end{warnbox}
