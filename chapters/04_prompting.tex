\chapter{Prompting That Works}
\label{ch:prompting}

\begin{itshape}
Your prompts work, but they are inconsistent.
Sometimes Claude nails it on the first try; sometimes you spend three rounds
correcting misunderstandings. The gap is not randomness---it is precision.
\end{itshape}

In \cref{ch:first-session}, you learned three prompting basics:
be specific, think step by step, include verification criteria.
This chapter goes deeper: building a precision vocabulary,
structuring complex prompts, managing cost, and using extended thinking.

\section{Building a Precision Vocabulary}
\label{sec:precision}

\practitioner{Track how your requests could be stated more precisely.
Over time, develop a shared vocabulary between you and Claude.}

\begin{fullwidth}
\begin{tabular}{@{}p{5cm}p{7cm}@{}}
\toprule
\textbf{Natural Language} & \textbf{Precise Version} \\
\midrule
``Clean this data'' & \code{validate schema, impute nulls with median, drop rows where target is NaN} \\
``Train a model'' & \code{fit XGBoost on train split, evaluate AUC on val, log params to MLflow} \\
``Check if this works'' & \code{validate: run pytest, check no data leakage, verify feature distributions match prod} \\
``Add error handling'' & \code{add validation to build\_features(): raise ValueError on schema mismatch, log and skip rows with >50\% NaN} \\
\bottomrule
\end{tabular}
\end{fullwidth}

\margintip{Precision compounds. Practitioners report that shared vocabulary
can reduce correction rounds by 2--3$\times$---a plausible estimate,
though hard to measure precisely and workload-dependent.}

\begin{whybox}[Why Precision Vocabulary Compounds]
Precision is not just about saving correction rounds in a single session.
It builds a shared language between you and Claude. When your CLAUDE.md
says ``validate schema'' and your prompts say ``validate schema,''
Claude interprets both consistently. This alignment compounds:
your prompts become shorter, your CLAUDE.md rules more effective,
and your correction rate drops---not linearly, but exponentially
as the vocabulary stabilizes.
\end{whybox}

The pattern for building vocabulary:
\begin{enumerate}
  \item After each interaction, note how the request could have been clearer.
  \item Identify recurring request patterns (create, diagnose, refactor, validate).
  \item Document these patterns in your project nomenclature.
  \item Use the precise version in future requests.
\end{enumerate}

\marginnote[Cross-Ref]{For using precision prompts in collaborative reasoning,
see \cref{ch:thinking-partner}.}

\section{Structuring Complex Prompts}
\label{sec:structure}

\subsection{XML Tags for Multi-Component Prompts}

\official{For complex prompts, use XML tags to separate concerns:\sourceurl{https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/overview}}

\begin{minted}{xml}
<context>
The churn prediction model uses features from
src/features/customer.py. Current AUC is 0.72
on validation.
</context>

<task>
Add recency features: days since last purchase,
days since last login.
Compute from the events table.
</task>

<constraints>
- No data leakage: features must use only
  pre-churn data
- Must work with the existing FeatureStore
  interface
- Include unit tests for the new features
</constraints>

<verification>
Run: pytest tests/features/ -v
All existing tests must still pass.
Verify: no future-dated features in test set.
</verification>
\end{minted}

\subsection{Rich Inputs}

\official{Use \code{@file} to include files, paste screenshots,
pipe data from \code{stdin}.\sourceurl{https://code.claude.com/docs/en/best-practices}}
Real data beats verbal descriptions.

\begin{fullwidth}
\begin{tabular}{@{}lp{7cm}@{}}
\toprule
\textbf{Method} & \textbf{When to Use} \\
\midrule
\code{@file} or \code{@dir/} & Load file or directory content before Claude responds.
  Preferred over describing code. \\
Image paste & Copy/paste or drag-and-drop screenshots, diagrams,
  error messages directly into the prompt. \\
\code{cat file | claude} & Pipe data from other tools. Useful for logs,
  command output, or data samples. \\
URL allowlisting & Use \code{/permissions} to allow frequently-used doc sites.
  Claude can then fetch reference material directly. \\
\bottomrule
\end{tabular}
\end{fullwidth}

\begin{minted}{text}
Look at @src/features/customer.py
and @tests/features/test_customer.py.
The feature builder computes 12 features
but has no validation for missing values.
Add validation following existing patterns.
\end{minted}

\margintip{\code{@} references load content before Claude responds---more
efficient than asking Claude to \code{Read} the file itself, and it ensures
the context is available from the first reasoning step.}

\begin{minted}{bash}
# Pipe error logs for diagnosis
tail -100 app.log | claude -p "Diagnose the errors"

# Pipe test output for analysis
pytest tests/ -v 2>&1 | claude -p "Summarize failures"
\end{minted}

\section{Extended Thinking}
\label{sec:thinking}

\marginnote[Official]{On by default. Toggle: Alt+T. Opus 4.6: adaptive thinking
with effort controls.\sourceurl{https://platform.claude.com/docs/en/build-with-claude/extended-thinking}}

\official{Extended thinking lets Claude reason through complex problems
before responding.\sourceurl{https://platform.claude.com/docs/en/build-with-claude/extended-thinking}} On Opus 4.6, thinking is \textbf{adaptive}---the model
decides how much to think based on problem complexity.

\subsection{Effort Controls}

\marginnote[Official]{Set effort: \code{/effort low|medium|high|max|auto},
model picker slider, or \code{CLAUDE\_CODE\_EFFORT\_LEVEL} env
var.\sourceurl{https://code.claude.com/docs/en/model-config}}

\begin{description}
  \item[\code{low}] Minimal thinking. Best for: simple lookups, formatting, boilerplate.
  \item[\code{medium}] Moderate analysis. Best for: standard coding tasks, code reviews.
    \emph{Default for Max/Team subscribers on Opus~4.6.}
  \item[\code{high}] Deep reasoning. Best for: architecture decisions, complex debugging.
  \item[\code{max}] Deepest reasoning with no token constraint.
    \textbf{Opus~4.6 only, session-scoped} (does not persist across sessions).
    Best for: strategic decisions, novel problems requiring exhaustive analysis.
  \item[\code{auto}] Resets effort to the model's default behavior.
    Use when you want to undo a manual effort override and let the model
    choose its own reasoning depth.
\end{description}

\practitioner{The keyword \code{ultrathink} in any prompt escalates to \code{high}
effort for one turn---useful for ad-hoc deep analysis without changing
your session default.}

\official{Interleaved thinking\sourceurl{https://platform.claude.com/docs/en/build-with-claude/extended-thinking}}: Claude can think between tool calls,
enabling nuanced multi-step workflows where each step's reasoning
informs the next.

\marginnote[Cross-Ref]{Extended thinking is especially valuable during
collaborative design sessions (\cref{ch:thinking-partner}).}

\subsection{When to Enable vs.\ Disable}

\begin{decisionbox}[Extended Thinking]
\textbf{Enable} when: the task requires multi-step reasoning, architectural
decisions, debugging where the root cause is unclear, or code review
where you want to see the thought process.

\textbf{Disable} when: the task is simple (formatting, boilerplate),
latency matters more than depth, or you are running bulk operations
where speed dominates.

\textbf{Budget note}: Thinking tokens add to your bill and consume
context budget. In a long session with context already at 50\%,
heavy thinking can push you past the degradation threshold faster.
Monitor \code{/context} when using extended thinking in long sessions.
\end{decisionbox}

\margincost{Thinking tokens are billed as output tokens. Deep thinking
on a complex problem can generate thousands of thinking tokens---visible
in session cost but not in the response.}

\marginnote[Cross-Ref]{Thinking blocks are compaction-resistant:
auto-compaction cannot summarize them. See \cref{ch:context}
for mitigation strategies.}

\section{Cost Optimization}
\label{sec:cost}

\margincost{Prompt caching: up to 90\% on cached reads. Batch API: 50\% discount.
Combined: up to 70\%+ savings (workload-dependent).\sourceurl{https://platform.claude.com/docs/en/build-with-claude/prompt-caching}}

\subsection{Prompt Caching}

\official{Prompt caching reduces input costs by 90\% for repeated content.\sourceurl{https://platform.claude.com/docs/en/build-with-claude/prompt-caching}}

\begin{description}
  \item[Ephemeral (5-minute TTL)] Automatic for content appearing in
    multiple requests within a short window.
  \item[Persistent (1-hour TTL)] Explicit cache breakpoints for content you know
    will be reused: tool definitions, system prompts, reference documents.
\end{description}

\subsection{Batch API}

\official{50\% discount for asynchronous
processing.\sourceurl{https://platform.claude.com/docs/en/build-with-claude/batch-processing}}
Submit up to 100,000 requests per batch (256~MB max).
Most batches complete within 1 hour; results available within 24 hours.
Combinable with caching for up to 70\%+ total savings (workload-dependent).

Best for: bulk migrations, code review across many files, documentation generation.

\subsection{Model Selection}

\begin{fullwidth}
\begin{tabular}{@{}llp{6cm}@{}}
\toprule
\textbf{Model Class} & \textbf{Strength} & \textbf{Best For} \\
\midrule
Haiku 4.5 & Speed, lowest cost & Simple tasks, high volume, formatting \\
Sonnet 4.6 & Balance of speed and capability & Most coding tasks, daily development \\
Opus 4.6 & Frontier reasoning & Complex architecture, multi-file refactoring \\
\bottomrule
\end{tabular}
\end{fullwidth}

\margincost{Pricing changes frequently. Check current rates before planning budgets.\sourceurl{https://platform.claude.com/docs/en/about-claude/pricing}}

\practitioner{Default to Sonnet for development work. Escalate to Opus for
architecture decisions, complex debugging, and multi-file refactoring.
Use Haiku for bulk operations and simple formatting tasks.}

\subsection{Fast Mode (Research Preview)}

\official{Fast mode makes Opus 4.6 responses 2.5$\times$ faster at higher
per-token cost (\$30/\$150 per MTok). Same model, same quality---different
API configuration prioritizing speed.\sourceurl{https://code.claude.com/docs/en/fast-mode}}

\begin{description}
  \item[Toggle] \code{/fast} or \code{Alt+O}. A bolt icon
    appears next to the prompt while active.
  \item[Cost] Flat pricing across the full 1M context window.
    Billed to extra usage, not plan limits.
  \item[Fallback] On rate limit, automatically reverts to standard Opus
    (icon grays out), then re-enables when cooldown expires.
  \item[Persistence] On by default across sessions. Admins can require
    per-session opt-in via \code{fastModePerSessionOptIn}.
\end{description}

\marginnote[Warning]{Switching to fast mode mid-conversation reprices
the \emph{entire} cached context at the fast rate. Enable at session
start for best cost efficiency.}

\begin{decisionbox}[Fast Mode vs.\ Effort Level]
\textbf{Fast mode}: same quality, lower latency, higher cost.\\
\textbf{Lower effort}: less thinking, faster responses, potentially lower
quality on complex tasks.\\
\textbf{Combine both}: fast mode + low effort for maximum speed on
straightforward tasks.
\end{decisionbox}

by up to 60--80\% through caching.
\end{keyinsight}
