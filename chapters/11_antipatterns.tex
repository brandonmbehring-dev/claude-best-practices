% Chapter 11: Anti-Patterns & Recovery
\chapter{Anti-Patterns and Recovery}
\label{ch:antipatterns}

\begin{itshape}
Three hours in, Claude is hallucinating function names and ignoring
your CLAUDE.md rules. What went wrong? More importantly: how do you escape?
\end{itshape}

Every tool has characteristic misuse patterns.
These eight anti-patterns are the most common ways developers
undermine their productivity with Claude Code.
Each includes the symptom, root cause, prevention,
\emph{and a recovery guide for when you are already stuck}.

% -------------------------------------------------------------------
\section{Context Overload}

\index{anti-patterns!context overload}\antipattern{Context Overload}{%
Claude ignores important rules. Instructions from CLAUDE.md are followed
inconsistently. Behavior degrades over long sessions.}{%
Hub-and-spoke architecture (\cref{ch:architecture}).
Conditional rules with \code{paths:} frontmatter.
Hooks for non-negotiable standards.
Keep core CLAUDE.md under $\sim$300 lines.
}

\textbf{Root cause:} CLAUDE.md has grown to contain every rule, convention,
and preference accumulated over months. Claude's attention dilutes
across all of it, and critical rules get the same weight as minor preferences.

\begin{fullwidth}
\begin{beforeafter}
\before
\begin{minted}{text}
# CLAUDE.md — 650 lines
Includes: git conventions, code style, architecture notes,
deployment procedures, 12 module-specific rules, personal
preferences, historical decisions, aspirational goals...
\end{minted}

\after
\begin{minted}{text}
# CLAUDE.md — 80 lines (core project rules)
# .claude/rules/backend.md — paths: backend/**/*.py
# .claude/rules/frontend.md — paths: frontend/**/*.tsx
# @~/shared-patterns/git.md — imported
# Hooks enforce: formatting, tests, lint
\end{minted}
\end{beforeafter}
\end{fullwidth}

\recovery{Context Overload}{%
Claude is ignoring rules that are in your CLAUDE.md.
Instructions work at session start but fail after 30 minutes.}{%
\begin{enumerate}
  \item Count lines in CLAUDE.md. If over 300: split.
  \item Move module-specific rules to \code{.claude/rules/} with \code{paths:}.
  \item Move shared patterns to hub imports.
  \item Move non-negotiable standards to hooks.
  \item What remains should be project-wide essentials only.
\end{enumerate}
}

\section{The Kitchen Sink Session}

\index{anti-patterns!kitchen sink session}\antipattern{Kitchen Sink Session}{%
Performance degrades midway through a session. Claude repeats itself,
forgets earlier decisions, or produces lower-quality output.}{%
Use \code{/clear} between unrelated tasks.
One session per logical task.
Use \code{/compact} if the task needs accumulated context.
}

\textbf{Root cause:} Multiple unrelated tasks in a single session.
Each task's context remains, consuming tokens
that contribute nothing to the current task.

\recovery{Kitchen Sink Session}{%
You are 90 minutes into a session that started with debugging,
moved to feature work, and now involves documentation.
Claude's responses are noticeably worse than at session start.}{%
Stop. \code{/clear}. Start a fresh session for the current task only.
Before clearing, note your current state in CURRENT\_WORK.md
so you do not lose context about what you were doing.
}

\section{Over-Correcting}

\index{anti-patterns!over-correcting}\antipattern{Over-Correcting}{%
Three or more rounds of ``no, that's not what I meant'' followed by
increasingly desperate attempts at the same task.}{%
Two-failure rule (\cref{sec:two-failure}): after two failed corrections,
\code{/clear} and write a better initial prompt.
}

\textbf{Root cause:} Each correction adds noise---the original error,
your correction, Claude's acknowledgment, and its retry.
After three rounds, the context is dominated by failure patterns.

\marginnote[Cross-Ref]{The hypothesis debugging workflow
in \cref{ch:thinking-partner} prevents over-correction by
structuring the problem before the first prompt.}

\recovery{Over-Correcting}{%
You are on correction round 4. Claude keeps making the same mistake
with slight variations.}{%
\begin{enumerate}
  \item \code{/clear} immediately.
  \item Before re-prompting, write down exactly what you want
    (on paper or in a scratch file).
  \item Include: what the function should do, an example input/output pair,
    and one specific constraint Claude kept violating.
  \item Re-prompt with this more precise request.
\end{enumerate}
}

\section{The Permanent Prototype}

\index{anti-patterns!permanent prototype}\antipattern{Permanent Prototype}{%
Code has been ``working'' for weeks but has no tests, no type hints,
no error handling. ``We'll add those later'' becomes permanent.}{%
Define explicit phase transition checklists in CLAUDE.md (\cref{sec:phases}).
Set a date for graduation from exploration to development.
}

\textbf{Root cause:} The exploration phase has no
defined exit criteria. Without an explicit transition, the code accumulates
users and dependencies while remaining at prototype quality.

\recovery{Permanent Prototype}{%
Your project has been in ``exploration'' mode for 6 weeks.
It has users. It has no tests.}{%
\begin{enumerate}
  \item Add a DEVELOPMENT phase to CLAUDE.md today, effective immediately.
  \item Have Claude write characterization tests (\cref{sec:refactoring-protocol})
    for the 3 most critical functions.
  \item Add a PreToolUse hook (matching \code{Bash}) that gates
    \code{git commit} on those tests passing.
  \item You now have a safety net. Refactor incrementally from here.
\end{enumerate}
}

\section{Pipeline Direction Violations}

\index{anti-patterns!pipeline direction}\antipattern{Pipeline Direction Violations}{%
Carefully edited downstream artifacts are overwritten when an upstream
script is re-run.}{%
Document pipeline flow direction.
Mark generated files: \code{\# GENERATED --- do not edit manually}.
}

\textbf{Root cause:} Editing a generated file, then re-running the generator.
The generator regenerates from source, destroying manual edits.

\recovery{Pipeline Direction Violations}{%
You just ran \code{extract\_features.py} and it overwrote 2 hours of
manual YAML edits.}{%
\begin{enumerate}
  \item \code{git checkout -- path/to/overwritten/files} to restore.
  \item Add \code{\# GENERATED --- do not edit manually} to generated files.
  \item If manual edits are needed, edit the \emph{source} (.tex, .py)
    and re-generate. Never edit downstream.
\end{enumerate}
}

\section{The Verification Gap}

\index{anti-patterns!verification gap}\antipattern{Verification Gap}{%
AI-generated code accepted without testing. Subtle bugs surface in
production weeks later.}{%
Always provide verification criteria (\cref{sec:verification}).
Tests with code---never after and separately.
Hook-enforced test requirements.
}

\textbf{Root cause:} AI-generated code \emph{looks} correct.
The syntax is clean, variable names are reasonable, the logic reads well.
This appearance of correctness is precisely why verification is essential.

\recovery{Verification Gap}{%
You have 1,500 lines of untested AI-generated code.
It ``works'' but you have zero confidence in it.}{%
\begin{enumerate}
  \item Do NOT try to test everything at once.
  \item Identify the 3 most critical functions (highest risk, most dependencies).
  \item Have Claude write tests for those 3 functions only.
  \item Add a PreToolUse hook gating commits on tests. No new untested code.
  \item Expand coverage incrementally: 3 more functions per week.
\end{enumerate}
}

\section{The Infinite Exploration}

\index{anti-patterns!infinite exploration}\antipattern{Infinite Exploration}{%
You ask Claude to ``investigate'' something without scoping it.
Claude reads hundreds of files, filling the context window with
exploration results that crowd out implementation.}{%
Scope investigations narrowly.
Use subagents for exploration so the research context does not
consume your main session (\cref{ch:agents}).
}

\textbf{Root cause:} Unbounded investigation prompts like
``look into how auth works'' give Claude no stopping criteria.
It reads every related file, consuming context that should be
reserved for the actual task.

\begin{fullwidth}
\begin{beforeafter}
\before
\begin{minted}{text}
Investigate how our authentication system works.
\end{minted}

\after
\begin{minted}{text}
Use a subagent to investigate how our auth system
handles token refresh, and whether we have any
existing OAuth utilities I should reuse.
Report back with: which files handle refresh,
what the token lifecycle is, and whether I can
reuse existing code for Google OAuth.
\end{minted}
\end{beforeafter}
\end{fullwidth}

\recovery{Infinite Exploration}{%
You asked Claude to ``look into'' something and it has read 40 files.
Your context is full of exploration results and you have not
started the actual task.}{%
\begin{enumerate}
  \item \code{/clear} immediately.
  \item Re-prompt with a scoped question and explicit deliverables.
  \item Or: delegate to a subagent so exploration runs in isolated context.
\end{enumerate}
}

\section{Big-Bang Refactoring}

\index{anti-patterns!big-bang refactoring}\antipattern{Big-Bang Refactoring}{%
A large rewrite fails partway through, leaving the codebase broken.}{%
Incremental protocol (\cref{sec:refactoring-protocol}):
Extract $\rightarrow$ Test $\rightarrow$ Harden $\rightarrow$ Promote.
Each step independently shippable. Commit after each step.
}

\textbf{Root cause:} The scope of the rewrite exceeds what can be held
in context. Claude loses track of the original behavior and introduces
regressions.

\recovery{Big-Bang Refactoring}{%
You are 3 hours into a rewrite. Half the tests fail.
The old code and new code are mixed together.}{%
\begin{enumerate}
  \item \code{git stash} the current mess.
  \item Return to the last working commit.
  \item Start the incremental protocol: extract ONE function,
    write characterization tests, refactor, verify, commit.
  \item Repeat. Each step takes 25 minutes and always leaves
    the code in a working state.
\end{enumerate}
}

% -------------------------------------------------------------------
\begin{keyinsight}
Every anti-pattern shares a common thread:
they arise from treating Claude as infinitely capable rather than
as a powerful but bounded system. Context is finite. Attention degrades.
Verification is essential. Working within these constraints---not
ignoring them---is what separates productive Claude usage from frustrating
Claude usage.

These are personal patterns. When you scale Claude to a team, new patterns
emerge---and the solutions shift from personal discipline to organizational
infrastructure. That is the subject of Part~IV.
\end{keyinsight}

\margintip{When debugging Claude itself, use \code{/debug} to inspect model,
session, and configuration state. Use \code{/status} for version and account info.}

\section{Systematic Diagnosis: The Four Failure Layers}
\label{sec:diagnosis}

\marginnote[Tip]{When Claude keeps failing,
diagnose the layer---not the symptom.
Fixing the wrong layer wastes time.}

Claude keeps making the same mistake across sessions.
Before blaming the model, work through the four layers in order:

\begin{enumerate}
  \item \textbf{Layer 1: The prompt.}
    Is your request ambiguous? Does it assume context Claude does not have?
    \emph{Test:} Rephrase the request with explicit constraints and
    an example of what ``correct'' looks like. If Claude succeeds,
    the problem was prompt specificity.

  \item \textbf{Layer 2: CLAUDE.md.}
    Is there a conflicting rule? A rule that is too vague to enforce?
    A rule that Claude interprets differently than you intended?
    \emph{Test:} Temporarily remove your CLAUDE.md (\code{mv .claude/CLAUDE.md
    .claude/CLAUDE.md.bak}), then retry. If the problem disappears,
    a rule is interfering. Add rules back incrementally to isolate
    the conflict.

  \item \textbf{Layer 3: The codebase.}
    Does the existing code teach Claude the wrong patterns?
    If your codebase has 50 functions using pattern A and you want
    pattern B, Claude will default to A regardless of instructions.
    \emph{Test:} Ask Claude \emph{why} it chose its approach.
    If it cites existing code as the reason, the codebase is the
    teacher and your instruction is the exception.
    Fix the instruction to be explicit: ``Do NOT follow the pattern
    in \code{src/legacy/}. Use the pattern shown in \code{src/v2/} instead.''

  \item \textbf{Layer 4: The model.}
    Genuine model limitations exist---certain reasoning patterns,
    mathematical computations, or domain-specific conventions that
    the model gets wrong consistently.
    \emph{Test:} Try the same task with extended thinking (\code{/effort max}).
    If it still fails, try with a different model (\code{/model sonnet}).
    If all models fail the same way, accept the limitation and
    design a workaround (verification step, hook, or manual review).
\end{enumerate}

\practitioner{In practice, 80\% of persistent failures are Layer~1
(prompt) or Layer~2 (CLAUDE.md). Practitioners jump to Layer~4
(``the model is wrong'') before checking whether their instructions
are unambiguous and conflict-free. The layered diagnosis forces you
to rule out the cheap fixes before concluding the model is at fault.}

\section{Testing Your CLAUDE.md}
\label{sec:testing-claude-md}

\marginnote[Tip]{An untested CLAUDE.md is an assumption,
not a standard.}

You added a rule to CLAUDE.md. How do you know it works?

\subsection*{The Smoke Test}

After adding or changing a rule:

\begin{enumerate}
  \item Start a fresh session (\code{/clear}).
  \item Ask Claude to do the thing the rule governs.
    Do not mention the rule---just describe the task.
  \item Check whether Claude follows the rule without being told.
\end{enumerate}

\noindent If Claude follows it: the rule works.
If Claude ignores it: the rule is either too vague, buried among
competing rules, or contradicted by codebase patterns (Layer~3).

\subsection*{The Adversarial Test}

For critical rules (security, compliance, data handling):

\begin{enumerate}
  \item Ask Claude to do something the rule prohibits.
    ``Write a function that reads from \code{.env} and logs
    the contents.''
  \item Check whether Claude refuses or flags the violation.
  \item If Claude complies without hesitation, the deny rule
    is not working. Check: is it in \code{settings.json} (enforced
    by the harness) or in CLAUDE.md (advisory, Claude may ignore)?
\end{enumerate}

\practitioner{Deny rules in \code{settings.json} are enforced
by the harness---Claude cannot bypass them. Rules in CLAUDE.md are
\emph{advisory}---Claude follows them because it is told to,
not because it is prevented from violating them.
For anything security-critical, use \code{settings.json} deny rules
or hooks, not CLAUDE.md.}

\begin{trybox}
Audit your most active ML project:
\begin{enumerate}
  \item Count lines in CLAUDE.md. Over 300? Flag for splitting.
  \item Check your last 5 sessions: how many had 3+ correction rounds?
  \item Is your project in an explicit development phase, or is it a
    permanent notebook prototype with no tests?
  \item Identify the single anti-pattern most affecting your productivity.
    Apply the recovery guide above.
\end{enumerate}
\end{trybox}
