\subsection{Data Protection}

\official{Key data protection features:}
\begin{itemize}
  \item \textbf{Encryption}: TLS 1.2+ in transit, AES-256 at rest.
  \item \textbf{Zero Data Retention (ZDR)}: Available for API and Enterprise plans.
  \item \textbf{No training on enterprise data}: Enterprise and API data is NOT
    used for model training by default. Explicit opt-in required.
  \item \textbf{BYOK}: Bring Your Own Key --- check current availability on the Trust Portal.
\end{itemize}

\marginenterprise{Enterprise/API data is never used for training by default. This is a contractual guarantee, not just a policy.\sourceurl{https://privacy.claude.com/en/articles/10023548-how-long-do-you-store-my-data}}

\subsection{Practical Security Configuration}

\practitioner{Enforce deny rules for sensitive files across all team members:}

\begin{minted}{json}
{
  "permissions": {
    "deny": [
      "Read(.env*)",
      "Read(secrets/**)",
      "Read(**/*.pem)",
      "Read(**/*.key)",
      "Read(**/credentials*)",
      "Read(**/.aws/**)",
      "Read(**/.ssh/**)",
      "Bash(sudo:*)",
      "Bash(rm -rf /)"
    ]
  }
}
\end{minted}

\marginnote[Official]{Claude Code included with Team plan seats. Shared CLAUDE.md in VCS.\sourceurl{https://support.claude.com/en/articles/9797531-what-is-the-enterprise-plan}}

\subsection{Managed Settings}

\official{IT administrators can deploy \code{.managed-settings.json}
files that override all other settings.} This enables:

\begin{itemize}
  \item Organization-wide deny rules (sensitive file access)
  \item Mandatory hooks (security scanning, compliance checks)
  \item Approved MCP server lists
  \item Model restrictions (e.g., Sonnet only for cost control)
\end{itemize}

\subsection{Convention: Committed vs.\ Local Settings}

\practitioner{Establish a team convention:}

\begin{description}
  \item[\code{settings.json}] Team standards, committed to git.
    Permissions, hooks, MCP configs everyone follows.
  \item[\code{settings.local.json}] Personal preferences, auto-gitignored.
    Model choice, output style, personal API tokens.
\end{description}

\section{Cost Optimization at Scale}
\label{sec:cost-scale}

\margincost{Prompt caching (90\%) + Batch API (50\%) = 70\%+ combined savings.\sourceurl{https://platform.claude.com/docs/en/build-with-claude/prompt-caching}}

\official{Cost management tools:}

\begin{description}
  \item[Prompt caching] 90\% input cost savings on repeated content.
  \item[Batch API] 50\% discount for asynchronous processing.
  \item[Pooled usage model] No per-seat licensing. Admin spending caps.
  \item[Effort controls] On Opus 4.6: intelligence/speed/cost tradeoff per request.
  \item[Model selection] Sonnet for most tasks, Opus for frontier reasoning.
    Haiku for bulk operations.
\end{description}

\subsection{Cost Reduction Strategy}

\begin{enumerate}
  \item \textbf{Optimize CLAUDE.md for caching.}
    Stable tool definitions and system prompts cache automatically.
    Restructure to put stable content first.
  \item \textbf{Use Batch API for bulk operations.}
    Code review, documentation generation, test scaffolding---all benefit
    from 50\% batch discounts.
  \item \textbf{Right-size models.}
    Sonnet handles 80\% of coding tasks. Opus for architecture and complex reasoning.
    Haiku for formatting and simple lookups.
  \item \textbf{Set spending caps.}
    Admin controls prevent runaway costs from long-running agent sessions.
\end{enumerate}

\begin{keyinsight}
Enterprise deployment is not about buying seats---it is about
building organizational capability. The technology is the easy part.
The hard part is establishing shared conventions (CLAUDE.md standards),
training teams on effective patterns (this handbook),
and measuring ROI (usage analytics + quality metrics).
\end{keyinsight}
